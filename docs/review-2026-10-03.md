# Repository review — October 3, 2026

## Scope and assessment

Reviewed source, configuration, CLI behavior, dependency discovery, registry
resolution, local apply transactions, lockfile regeneration, GitHub PR
reconciliation, setup action, release packaging, CI, and public documentation.
The starting revision was `64e1bbd99a11aea8756a78933f27264cbb7891a2`.

The strongest part of the project is its apply contract: byte verification,
reproducible detached worktrees, constrained package-manager commands, expected
path checks, rollback, and native GitHub merge rules. The immediate weaknesses
were discovery accuracy, platform assumptions, cancellation, and inconsistent
boundaries between standalone scans and fleet automation. This run repairs those
areas and refreshes workflow tooling. The continuation implements the six
follow-up contracts below. Supported ecosystems remain bounded by the documented
input forms; release publication and long-running fleet operation are separate
qualification steps.

## Compatibility decisions

The Go **1.25** minimum is retained. The remaining outdated module,
`golang.org/x/mod v0.41.0`, declares `go 1.26.0`. Accepting that update requires a
separate toolchain migration and documentation change. The updater correctly
refused to let `go mod tidy` make that decision implicitly.

Configuration schema 1 and report schema 2 remain unchanged. Intentional stricter
behavior includes rejecting symlinked configurations, extra YAML documents,
malformed workflow YAML, unsafe GitHub endpoints, and oversized selected
manifests. Go indirect dependencies and unsupported Cargo Git/private-registry
sources are no longer offered as direct public-registry updates. These exclusions
do not constitute complete inventory of unsupported sources.

### Additional failures found and repaired

Final review also found that an incomplete scan could leave a prior native
auto-merge request enabled. The runner now reads managed ownership and revokes
that request without closing the PR or deleting its branch. Preview remains
read-only; ambiguous ownership still blocks mutations.

Native Windows exposed checkout CRLF conversion shifting approved byte spans,
nonportable path normalization, unsupported directory fsync, and Unix-only mode
assumptions. Verified source bytes now seed detached worktrees. Git diagnostics
are separated from stdout so conversion warnings cannot become changed paths.
The source-byte contract remains strict if a package manager makes extra edits.

The first OCI fallback triggered a secret-scanner false positive on the Go
expression `auth.AccessToken`. Its reported fingerprint matched that expression,
not a credential. The fallback now iterates the two documented token response
fields; the existing security policy remains enforced.

Diff review now separates distant changes into contextual hunks, quotes unusual
paths, and caps the line-comparison table. Large replacements retain exact bytes
with broader hunks. Saved artifacts are integrity checked, not signed; their
trusted review channel remains necessary.

### Verification boundaries

- The full race suite passes across eight packages, with total statement coverage
  **75.0%** in the final local run. Target repository tests remain the
  compatibility gate for dependency upgrades.
- The executable fixtures include Go workspaces, real Cargo and npm operations,
  a Bun lifecycle trap, and NuGet project/imported MSBuild target traps. All
  required runtimes must be present; integration mode cannot silently skip one.
- Configuration schema 1 remains compatible. Report schema 2 adds optional
  policy/container evidence and blocked/unsupported statuses. Saved plans use
  schema 1; approval digests use domain `hooneedsupdates-plan-v2`.
- `golang.org/x/mod` remains at v0.40.0: v0.41.0 requires Go 1.26, while this
  project retains its Go 1.25 minimum. Regeneration rejects the unapproved Go
  directive change; a toolchain migration needs its own reviewed compatibility
  decision.
- Native tests establish platform execution; cross-builds establish archive
  production. Neither implies artifact signing, release publication, merging
  this PR, or deployed fleet acceptance.
