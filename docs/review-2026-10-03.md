# Repository review — October 3, 2026

## Scope and assessment

Reviewed source, configuration, CLI behavior, dependency discovery, registry
resolution, local apply transactions, lockfile regeneration, GitHub PR
reconciliation, setup action, release packaging, CI, and public documentation.
The starting revision was `64e1bbd99a11aea8756a78933f27264cbb7891a2`.

The strongest part of the project is its apply contract: byte verification,
reproducible detached worktrees, constrained package-manager commands, expected
path checks, rollback, and native GitHub merge rules. The immediate weaknesses
were discovery accuracy, platform assumptions, cancellation, and inconsistent
boundaries between standalone scans and fleet automation. This run repairs those
areas and refreshes workflow tooling. It does not establish the full manager
coverage or stable automation contract described in the later roadmap stages.

## Compatibility decisions

The Go **1.25** minimum is retained. The remaining outdated module,
`golang.org/x/mod v0.41.0`, declares `go 1.26.0`. Accepting that update requires a
separate toolchain migration and documentation change. The updater correctly
refused to let `go mod tidy` make that decision implicitly.

Configuration schema 1 and report schema 2 remain unchanged. Intentional stricter
behavior includes rejecting symlinked configurations, extra YAML documents,
malformed workflow YAML, unsafe GitHub endpoints, and oversized selected
manifests. Go indirect dependencies and unsupported Cargo Git/private-registry
sources are no longer offered as direct public-registry updates. These exclusions
do not constitute complete inventory of unsupported sources.

## Prioritized follow-up work

### 1. Digest-aware container updates and honest coverage reporting

The Docker extractor currently skips `image:tag@sha256:...` references, including
this repository's own base images. Updating only the tag while retaining the old
digest would be incorrect, so a complete change must resolve and edit both fields
as one reviewed unit. Add fixtures for multi-stage images, platforms, digest-only
pins, private registries, aliases, and comments. Inventory must distinguish
unsupported inputs from genuinely current dependencies. Zero unresolved findings
currently describes the detected inventory, not every dependency in a repository.

### 2. Saved plans and explicit apply policy

A preview currently rescans upstream when `--write` is run. Provide a durable,
validated plan input with versioned JSON schema, verified file state, and a clear
policy for unresolved or blocked entries. Show proposed byte changes as a diff
before writing. Preserve the current no-command-execution contract.

### 3. PR lifecycle concurrency and pagination

First publication and updates now use leases. Stale cleanup still deletes refs
through the REST API without a conditional SHA, and pull discovery considers only
100 results. Design conditional stale deletion and bounded pagination together
with ownership evidence and tests for concurrent branch changes, closed/merged
PRs, base-branch changes, and ambiguous history.

### 4. Grouping, minimum age, and compatibility windows

Implement the remaining v0.3 policy work as vertical slices with fixtures and
versioned evidence. Update-type names alone do not demonstrate API compatibility,
especially for pre-1.0 tools. Require repository checks and reviews to remain
independent gates; coordinated action SHA/input changes must stay atomic.

### 5. Native platform and package-manager qualification

The new macOS check covers a reproduced failure. Add native Windows tests after
addressing platform-specific symlink privileges and directory syncing. Expand
executable tests to Go workspaces, Bun, and static NuGet projects, and specify
minimum package-manager versions. Cross-compilation is a useful release gate but
cannot establish filesystem transaction behavior on another OS.

### 6. Maintainability and stable contract

Split the large extraction and lockfile files by ecosystem as behavior is changed;
keep byte-span, containment, and transaction helpers shared. Publish configuration
and evidence schemas, recovery examples, and migration tests. Add parser fuzzing
and cancellation/resource-budget tests based on concrete failure cases. Keep
roadmap status separate from verified release and deployed automation state.
